## 第二组 · 按提案收（打包）

**可信智能体线（记忆 A1–A5 / 前端 B1–B5 / 指标 C）**
- A1 三元重排信号入记忆规格：importance+last_accessed 只重排会话性注入份额，不管事实通道；衰减按「天」量级重标定，不照搬 0.995/小时；importance 三分来源、禁止行动中实时自评
- A2 巩固双轨触发：显著性预算 + 夜间兜底，触发本身入 M0
- A3 巩固产出三关校验链：引证逐字命中 → tombstone 检查 → 冲突检查，全过才以 inferred 入册，不过进 M6 待核队列
- A4 M2 增设关系子集：共同事件、内部指称表（带首次出处）、纠正-修复记录
- A5 回忆呈现分级入注入规格：默认内部指称档、引证仅限争议/裁决、禁止炫忆
- B1 小人行为＝确定性映射表（在途状态×M6 账本×时段），禁止 LLM 实时决定行为
- B2 偏差优先呈现：状态变化触发显式行为，与 M0 事件一一对应、可点击回溯
- B3 Barks 查表层：无记忆命中宁可沉默，不编词
- B4 M6 账本的 Notebook 式视图作为「秘书没丢事」的主界面候选
- B5 离线/夜间值班态 + 晨间例程化汇总动作
- C 三指标操作定义与分母口径按 §7 表；新增月度访谈自检（冻结快照题库对金标）、季度消融自检（关单层量边际贡献）两件仪器

**开源维护线**
- 头三工作流及顺序与验收信号：①Intake 流水线 → ②复现—修复—自验链（红绿证据完整率 100% 硬卡、误合零容忍降级）→ ③Reply Desk 发声层
- 对外动作按目标仓 AI 政策分级（入对外点规范）；自动首响只许信息确认与模板索取两类
- 复现四终态入册，not-reproduced 永不单独触发关闭；弱化四元组抽取（版本/平台/步骤/报错原文）缺项走 needs-info 不许猜
- GitHub 内容生成限额包络（≤80/分、≤500/时）入对外动作与成本规范，撞限停批不重试
- 审查器阈值只用自家仓库历史 PR 回放标定（金标集纪律），不采厂商基准

**沉淀作者面线**
- 沉淀包格式：一个文件夹三读者（manifest/正文 prose/cases/），SKILL.md 骨架 + 判局语义（kind 含 standing-order 与 counter-rule、trigger 一等字段、params 类型化、无参数⇒私有）
- 创作回路：秘书访谈（≤7 问选项优先）→ 标例子同时产金标集 → 回放报告卡 → 影子 → 上梯；机器门拒绝必须大声（理由+修法+秘书代修），与证据门「还不够」严格分开
- 十个种子沉淀随箱出厂（一 kind 一插入点各一，自家狗粮即包格式）
- 信任三阶段：owner → 具名协作者 → 公开画廊，scope 写进格式
- 降级外交：证据标准一视同仁、流程不同（证据卡→警告期→修订/申诉/退役，永不静默改删）
- 开放问题处置：正文/impl 双轨按 kind 分策、待成本口径落定（Q2 暂挂）；无历史的新包提供「合成病例」路径（Q3 倾向要）；访谈打扰进 KPI 分母（Q4）；协作者批准流随 P2 立项再议（Q5）；repair hint 公开前过内容门、与安全点联审（Q6）

**飞书线**
- 活状态板形态：CardKit + 滚动重发 + 节流合并；过期裁决卡（>14 天）秘书侧重发并把旧卡刷为已过期
- 权限清单纳入 `im:message.group_msg`（群全量消息）
- 长输出一律卡片形态（text/post 不承载排版）；定时发送靠自家调度器
