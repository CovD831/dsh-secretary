# F1 自定义形象设计卡（立绘 + 像素小人）

> 2026-11-23 · 限时 25 分钟，只读设计。事实校正：表情枚举在 `src/speech-config.ts` 的 `MOODS`（简报写作 constants.ts）；立绘 192×240→显示 384×480；小人 cell **32×48**、内容 24×36、脚锚 (16,44)、帧表 6×4=24 格（简报的 48×64 与冻结规格 §3 不符，按 32×48 落）。

## 1. 角色包格式

形象包 = 目录 + `manifest.json`。预设随包只读；用户包复制进插件数据目录，原图留在 `raw/` 供重跑并记哈希。`generation` 只记服务标识/模型/seed/提示词，**不存 key**（凭据走受控设施，STANDARDS §9）。

```json
{
  "v": 1, "id": "boss-ai-01", "name": "老板的秘书",
  "source": "ai",                                  // preset | ai | import
  "createdAt": "2026-11-23T10:00:00+08:00",
  "portrait": { "native": [192, 240], "anchor": [96, 240],
    "moods": { "neutral": "portrait/neutral.png", "working": "portrait/working.png",
               "happy": "portrait/happy.png", "concerned": "portrait/concerned.png" } },
  "sprite": { "cell": [32, 48], "content": [24, 36], "feetAnchor": [16, 44],
    "sheet": "sprite/secretary.png", "grid": [6, 4], "facing": ["NE", "NW", "SE", "SW"],
    "mirror": { "NW": "NE", "SW": "SE" } },
  "palette": { "quantized": true, "colors": 46 },
  "generation": { "provider": "user-configured", "model": "…", "seed": 12345,
                  "prompt": "…", "raw": "raw/neutral-4x.png" }
}
```

> 注释不落盘。四表情缺任一即拒绝切换该包，不静默回退（回退会造出第三份状态）。帧表 v1 只收整表，不收逐帧散文件。

## 2. 规整管线（导入 / 生成共用）

| 步骤 | 做法 | 失败处理 |
|---|---|---|
| 尺寸 | 立绘只收 192×240 / 384×480 / 768×960；帧表只收 6×4、cell 32×48、整体 192×192 / 384×384；只允许整数倍最近邻缩放 | 判废，回可用尺寸 |
| 去背景 | 优先真 alpha；否则四角取背景色、四向泛洪（容差 28）。四角均为同灰度浅色 → 判 AI 假棋盘格，白/灰两档一并剔除 | 主体贴边或仍有残底 → 提示 |
| 量化 | Oklab 最近色映射 46 色；alpha<128 归 0，只留 0/255 | 越界像素计数进 metrics，不阻断 |
| 锚点 | 立绘 bbox 底边中点写 (96,240)；帧表以站姿帧全局最低脚线定统一偏移，整表共用 | 逐帧贴底会抖，按整表重排后复检 |
| 入库 | 写 `metrics.json`（原尺寸/色数/最大 ΔE/半透明清除数/角 alpha/残底数），全过才落盘 | 失败只留 raw/，不留半成品包 |

检查清单（全过才入库）：原生尺寸精确；alpha 仅 0/255 且四角为 0；`quantized:true` 时非色板像素 0；外轮廓 1px `#1A1412` 闭合（启发式：轮廓像素邻透明）；四表情文件尺寸一致、帧表 6×4；2× 复查无灰边。

提示文案：

- 「图片 683×854 不是 192×240 的整数倍，请导出 384×480 或 768×960。」
- 「检测到棋盘格假透明，已去除；若仍有白边，请改用真 alpha PNG。」
- 「角色贴到画布边缘，可能被裁：请四周留 ≥8px 透明边距。」
- 「缺少 concerned：gate 拦截时秘书将看不出紧张，请补图或换包。」
- 「帧表为 5×4，需 6×4；每格 32×48。」
- 「已保留原色：形象与房间色温可能不同框（46 色契约未满足）。」

## 3. 一图派生多表情 / 多动作

| 方案 | 适用 | 一致性 | 成本 | 结论 |
|---|---|---|---|---|
| 图生图（固定参考 + seed，只改情绪/朝向词） | 立绘、帧表 | 中：脸/配饰会漂 | 立绘 4 次；帧表整表 1 次 | 帧表整表优先；逐帧 24 次漂移累积，弃 |
| 仅换表情区（固定眼/眉/嘴矩形叠合） | 立绘 | 高：身份像素级不变 | 1 底图 + 4 局部 | 推荐预设/导入；3/4 视角程序化贴片不成立〔推断〕 |
| 生成两向 + 镜像 | 帧表 | 高（同图内） | 2 次 | 推荐 NE/SE 生成、NW/SW 镜像；不对称配饰会镜像错〔推断〕 |
| 手工导入多张 | 两者 | 由用户负责 | 最高 | 保底，始终开放 |

- 实测：≤32px 生成糊成噪点，≥192px 可用。故一律先出 4×（立绘 768×960、帧表 768×768）再整数降采样，不让模型直接出 192×240。
- 「模型直接出 24×32 小人」不可行〔实测〕；参考图/seed 是否可用取决于用户自配服务〔推断〕。

## 4. 存放与切换

- 用户包：`$DSH_HOME/plugins/dsh-secretary/avatars/<id>/`（与 `event-log/` 同级）；预设只读随 dist 发。
- 当前形象：`$DSH_HOME/plugins/dsh-secretary/settings/secretary.json`，`{v, avatarId, rev, updatedAt}`；切换入口在设置面板，不在房间。
- 真相归类（供队长裁决）：
  - A. 新建第三类「用户设置」：小、版本化、非追加、不入日志；前端只读，写入走设置 API 且失败显式报错。**推荐**。
  - B. 归入定义侧（注册表/配置）：可接受，但会模糊「注册表只管 gate 定义」的边界。
  - C. 记为事件：反对。切换是偏好不是发生真相；重放日志会重演偏好，且给前端开了写口。
- 与 §3「两类真相」的接口：形象包是资产，不做 gate 式注册，load 时校验 manifest；切换记录不在「从日志重建」范围内，需在检查项单列，否则重建验收会误判。

## 5. 需老板拍板（2 个）

1. 自定义是否强制 46 色？建议：AI 路径强制；导入默认量化、可关，关闭时显示「非合拍」标签（仍强制二值 alpha + 1px 描边）。
2. 自定义范围：只换秘书（立绘 + 小人），还是 Lead/worker 也可换？建议首期只换秘书，Lead/worker 沿用预设帧表与换色。
## 老板裁定（2026-11-23）
- **不做任意图片导入**。自定义形象只有一条路：用户在插件内配置自己的生图模型，填写想要的形象描述；插件套用我们预置的风格提示词、尺寸与后处理管线生成。上文「导入」相关设计作废。
- 因此第 1 问自动解决：所有自定义形象一律经预置管线量化到冻结色板。
