## 1. 最重要的三个事实（决定新仓怎么立）

1. **底座已经变了**：DeepSeek Harness 本体最新 **0.2.2-rc.5（2026-11-18）**，至今无任何非 rc 稳定版。插件体系是 Cordis（无特权核心可 patch、bundle/profile/preset 分层、官方扩展点表齐全）。SuperAgent 钉的 0.2.1-rc.3 已落后两代。新仓必须钉版本 + 留升级审计流程，不能假设 API 稳定。
2. **官方已经有 team 了——但老板的判局层基本没被吃掉**。官方本体自带实验性 agent-team（Lead+命名队友+共享任务 DAG，官方 SDK 文档证实经 `sdk` profile + patch `agent-team / defaultEnabled: true` 开启）；NanmiCoder 上游也活着（v0.1.31，2026-11-18）。逐项审计结论：**老板 15 个 gate 里 13 个仍独有、2 个部分重叠、0 个被完全取代**；注册表/六插入点/requires 输入面审计/judgement-triage/friction-triage/证伪语料全部仍是原创。真正作废的只有旧 `quality-gates.ts` 快照和 tools 拆分这类重构层。冲突不在 gate 本身，在**系统层五处**（见 §4 决策）。
3. **融合论成立约 90%，缺的 10% 恰好是老板要写的**：fusion-map 逐点核实——10 个原子点每个的*机制*都有现成开源件，但每个点的*判据*（何时触发、什么算过、冲突谁赢）没有任何项目提供。上报即缺陷信号（点 4）甚至连机制都无直接对应物，是相对 SuperAgent 的真增量；且全生态**没有任何项目公布过「打扰随时间下降」的度量**——这是可占的差异化，也是 RSI 线的 KPI。

```

          Channel/AccountId/AgentId/SessionKey 确定性路由（非模型路由）；
          国内通道参照 nanobot / baojingyu 多通道版。通道只是适配器。
[秘书层]  SuperAgent Router 的升维：唯一长命会话，管辖域=注册表内全部工作区。
          执行 superagent-deepening §4 的《秘书响应性契约》11 条，核心：
          R1 永不执行（工具面物理拿不到执行工具，比原型更严——原型 Router
             还有 5s 上限的只读 shell；已定 2026-11-21：秘书零执行工具，只有受限结构化状态查询）；
          R3 先 ack 再派工；R4 永不等（等 worker 靠队列/事件，不靠阻塞）；
          R5 状态查询走预留特权槽（借原型 +1 privileged slot）永不排队；

          （gates 配置 / mandate / 通道 Correlation / 凭证隔离）。

          (admission/contract/dispatch/completion/delivery/runtime) +

          (verify-rerun / changed-paths / absorb / convergence)。
──── 脊：统一事件总线 ────
fusion-map 点名：融合的隐藏脊柱是一套归一化事件 schema（ticket 生命周期、
gate 判定、上报、worker 状态）。各借来组件事件格式互不相通，没有这根脊，
```

**DSH 原生缺口（实查）**：本体**没有长期记忆**（只有 compaction + AGENTS.md，官方记忆方案是默认关闭的第三方 MCP）。记忆层要自选（文件双件套 Hermes 式 / MCP memory），别假设底座有。

## 3. 不要重建清单（直接依托 DSH / 借件）

| 不建 | 用什么 |
|---|---|
| 会话/子 agent/任务调度/状态存储 | DSH 本体（append-only session log、subagent、schedule/jobs 服务） |
| 插件装配/配置分层 | Cordis bundle + profile + patch（官方机制） |
| 权限预设/沙箱/工具级审批 | DSH permission presets + sandbox；实验性 Auto review 只管工具调用级，与 gates 的生命周期级分界、互不越界 |
| team 编排骨架 | 官方 agent-team 或 Nanmi 上游，二选一（决策①） |
| Router 异步骨架 | SuperAgent 原型 preset + Effects 队列/Passes 泵（代码模式照抄，MIT） |
| 持久分发/重试 | Temporal 或 Hatchet 二选一（fusion-map）；重试只许存在于一层 |
| 通道路由/多通道适配 | OpenClaw 路由模型（借模型不一定借码）、nanobot 国内通道 |
| 评测脚手架 | GEPA/DSPy（优化）+ promptfoo/DeepEval（质量门执行器）——借执行器，判据自写 |
| 策略引擎（如需） | OPA 或 Cedar 二选一，作 gate 判定引擎候选，不自研表达式语言 |
| L0 像素前端 | Pixel Agents（10,309★ MIT）的精灵状态机模式 + PixiJS；L2 永远只做深链跳回原始客户端，绝不重建 |

**只自建（判局胶水，即新仓的原创面）**：注册表 schema + 冲突裁决顺序；沉淀准入门（新 gate/skill 进库的 admission gate）；每类模块的 RSI 留存/收敛判据 + 收益台账；上报四分归因（缺失/错误/不可测/冲突）+ 衰减 KPI；秘书工具 deny-list；工作区注册表字段与路由判据；Mandate 内容模板与默认值；L0 状态枚举映射 + L1 卡片字段；硬门/软门分层 + judge 版本钉死。

## 4. 开发规范要点（治旧仓臃肿乱）

- **注册表是唯一真相**：gate 不注册不存在；注册条目必带触发点、输入面（requires）、判据、版本、fixture 指针——旧仓 `requires` 输入面审计直接升为入仓门槛。
- **语料从第一天冻结**：旧仓 gate-corpus（43 个真实任务）+ falsification-pairs 平移为新仓 CI 资产；新 gate 合入 = 单机制协议过线（family-disjoint 切分、≥3 seed、收益/成本双指标、证伪对同判）。
- **RSI 账本常规化**：LOO 先行→剪枝→LOI→冲突对（harness-rsi §执行序）；模块「已证明」状态可因模型/环境变更被降级（proven-demotion）；注意术语：RSI 无规范定义（唯一共识展开是 Recursive Self-Improvement），新仓文档须给出本项目操作定义，并与旧仓 `delivery.convergence`（成员状态收敛）显式区分命名。
- **版本钉死 + 升级审计**：DSH rc 迭代快且无稳定版；每次升级走旧仓已有 compatibility-audit 流程，judge/模型版本同样钉死。
- **状态存储收敛**：只许秘书层一份注册表 + DSH session log 两种真相，禁止每个借件自带一套 store 落地（fusion-map 列为融合头号死法）。
