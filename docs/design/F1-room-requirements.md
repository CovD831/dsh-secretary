> 2026-11-23 · 只取需求，不取实现。来源别名：REQ=`docs/REQUIREMENTS.md`；SPEC=`docs/PIXEL-ROOM-ENTRY-SPEC.md`；E2R=`docs/room-gen-algorithms.md`；SED=`docs/SINGLE-EXIT-DIRECTION.md`；OFF=`docs/OFFICE-WORLD-DESIGN.md`；DP=`docs/DECISIONS-PENDING.md`（均在 ~/Desktop/agent-teams-dev）。
> 阶段：**v1**=单房（PRD 前端支线 F1–F2）｜**v2**=预设楼+地块+用户自定义摆放｜**v3**=程序生长（种子拓扑/路网/庭院）。⚠=旧仓内部冲突或反复，详见 §4。

## 1. 需求清单

### A 房型生成
- A1 工作区=房间=一个完整工作空间（队长与成员同室，无「会议室」专属间）；新增工作区由系统自动扩建，用户不手工建房。SPEC §1/§2、SED §10-2、SED §11 — **v2**
- A2 房间=长命容器，团队=人员进出；房间身份用 `workspaceId`（稳定键），`title` 只作显示名（可重名）。OFF §0.1/§1、记忆裁定 — **v1**（单房也须身份键）
- A3 拓扑模板库 8–12 种、两两不同形（矩形变体/L/凸/T 枢纽/凹龛/斜切角），4-连通。SPEC §2.2、REQ §47(S1) — **v2**（v1 固定 1 套）
- A4 特征向量七维（拓扑/尺寸档/入门边/色板/地毯/墙饰/装饰件）+ seed ledger：未用组合优先，组合空间 >10⁴ 才复用「最久未用」。SPEC §2.2、E2R §5、room-estate — **v2**
- A5 ⚠ 尺寸档由家具套数决定（先定套、再定房间），档界不重叠。SPEC §2.3bis、room-generator — **v2**（与 v1 固定 16×12 冲突）
- A6 每房 ≥1 门，门落公共墙列；门位沿走廊 ±1–2 格独立相位，两侧禁对齐。SPEC §2.2、E2R §4.1/§5、OFF §3-1 — **v1**（单门）/ **v2**（门位相位）
- A7 窗、挂画、白板是墙挂件（沿墙参数 `at` + 离基线高度 `h`，半格吸附）；白板挂无窗墙。SPEC §2.3、REQ §68/§69/§72 — **v1**（装饰）/ v2（可编辑）
- A8 外轮廓矩形预留、外圈可作庭院地块；房间以包围盒档位落图。SPEC §2.4、E2R §5 — **v2**

### B 家具
- B1 「套」是摆放与出现的最小单位（办公套=桌+椅+灯；休憩套=茶几+沙发+落地灯），不是单件。SPEC §2.3bis、room-generator SUITE_TEMPLATES — **v1**（3–4 套足够）
- B2 每件有脚底格（footprint 的锚）与锚点；任意两件脚底格不重复。room-generator §2/§4、REQ §47(S5b)、DP footprint 条 — **v1**
- B3 朝向是数据纪律：偏移写在典则朝向，整套可 90° 旋转，绝对朝向写 `facing`；素材无转向帧时用水平镜像（不造「改数值画面不变」的假转向）。room-generator §2、REQ §70/§75 — **v1**（镜像）
- B4 硬约束（作用对象=套）：贴墙件靠墙、朝向件到门有净视线、套间 Chebyshev ≥2、不压门格与走廊格、门内侧主过道仍 ≥2 格空矩形。room-generator §4/§5、REQ §47(S5b) — **v1**
- B5 套组合模板（8 种配方）+ 共现规则（什么套可与什么套同房）。room-generator FURNITURE_TEMPLATES、SPEC §2.3bis — **v2**
- B6 种子三轴只作用于套级：整套换风格（禁单件混搭）/ 套数调尺寸 / 受规则约束的位置抖动。SPEC §2.3bis、REQ §47(S6c) — **v2**
- B7 装饰件无寓意、不承载任何状态语义；状态只在小人气泡与屏幕光。SPEC §2.3、OFF §2.3 — **v1**

### C 用户自定义摆放
- C1 放置/移动/删除/转向/撤销重做；选中即 55% 幽灵态 + 合法/非法着色 + 跟手预览。REQ §38/§70/§71/§72、DP — **v2**
- C2 碰撞：仅地板格可放、已占格不可叠、门口格禁放；墙挂件不走格位，只有 `(at,h)` 两个自由度。pixel-room-edit canPlace/doors、REQ §69 — **v2**
- C3 存档=覆盖层：`{version, removedBaseIds, placed[], wallItems[]}`；tmj/种子布局只作默认底稿，不因摆放被重写；⚠ 旧仓存 `localStorage`，新仓受「两类真相、派生不回写」约束应入 `storageDomain`（推断，见 §3-5）。pixel-room-edit EditLayout、REQ §38 — **v2**

### D 房间生命周期
- D1 五态：ACTIVE / DORMANT / COURTYARD_CANDIDATE / COURTYARD / PLOT；14 天无活动降沉睡、60 天出庭院候选。SPEC §3、room-estate 常量 — **v2**
- D2 自动迁移只有两条（ACTIVE→DORMANT、DORMANT→候选）；其余每步都出候选卡三选项（封存/保留观察/删为庭院），永不自动删除。SPEC §3、room-estate transitionRoom — **v2**
- D3 地图永不破相：删除=拆建为庭院，外轮廓恒完整，庭院/空地可被重建；旧房永不因新房或人数变化重排（重排摧毁位置记忆）。SPEC §3、SED §11、OFF §2.2-1 — **v2**
- D4 封存与保留观察必须不同形（封存=不再自动出卡，真活动才唤醒；保留观察=观察窗重新起算）。room-estate `sealedAt` — **v2**
- D6 确定性重算：同种子两次生成字节相同、同向量同 plan；布局可由（工作区创建序 + 种子）重放。room-generator、REQ §47(S8)/§110 — **v1**（单房即须具备）
- D7 ⚠ 纪念牌/历史感：旧仓只有「空地天然携带这里曾有项目的历史感」（SED §11）与「门牌」聊天用语，无正式条文；「庭院留纪念牌」来自新仓对话，属**推断**。SED §11 — **v2**

### E 多房连接
- E1 全部房间必须经走廊连通，且 ≥1 冗余环；环冗余度 H=E−V+1，目标 H=max(1,round(N/4))；桥数与 β 作读数。SPEC §2.4、E2R §4.3/§5 — **v3**
- E2 终选算法：房间质心→Delaunay 边集→Prim MST（权重=欧氏距离+0.5×|面积差|）→加非树边至 H→曼哈顿 L 形走廊（宽 2–3，禁斜走）→非对称门位。E2R §5 — **v3**
- E3 禁「对称双列」：门位不对齐、两侧进深分布不同、走廊宽度非均匀。E2R §4.1 — **v3**
- E4 走廊是生活区而非空带（每 6 格 ≥1 公共设施）；多房可排成一层楼（每行 2–3 间、走廊纵横贯通、空位要画出来）而非一条街。OFF §2.2/§3-2、SPEC §1 — **v2**

**冲突清单（需老板裁）**
1. **尺寸**：SPEC 说尺寸随套数变；OFF §2.2 说全楼统一格子（20×14）否则整层重排；新仓 F1 已写死 16×12。三者只能选一。
2. **入口优先级**：旧仓 REQ §27.5 用户裁定「房间不是默认入口，启动仍用文件夹页」；新仓 PRD §2.2 裁定像素房间是默认主页面。按 PRD，但旧裁定要留痕。
3. **画法**：REQ §32②「全程序绘制」vs §33「素材+瓦片地图」；2026-10-30 已收窄为「不许贴非自产位图」。新仓 PRD §3 用 AI 生图单一来源，按此执行，勿再引旧条款②原文。
4. **家具布置路线**：REQ §48-1「照参考图逐件手调」与「AI 出布局」均被用户否决（REQ §38、DP 布局权移交）；SPEC §2.3 的功能/装饰二分+面积撒点降级为 v1 参考，v2 以套+规则为准。
5. **桌面物**：DP 同日两份裁定相反——「自由像素位+显式 depth」vs「桌面 3×2 子格」。新仓按「桌面物是独立可编辑对象」设计即可，不必继承任一实现。
6. **多房形态与上限**：单间质量先行（REQ §47/§45）与 PRD v1 单房一致；但「一层楼」（OFF §2.2）与「走廊生长」（SPEC §2.4）谁先落、ACTIVE 房间 ≤1 还是 ≤2、每行 2–3 间，均未定，v2 开工前必须裁。

## 3. 数据模型硬约束（≤8；【原文】=旧仓条文/代码契约，【推断】=本文推论）

1. 【原文】家具必须有 footprint（占格集合）+ 脚底锚点；碰撞与靠墙判定一律以脚底格为对象（B2/B4、room-generator §4）。
2. 【原文】套实例 = `(suiteId, variantId, anchor, rotation)`，件偏移相对锚点固定；禁止按单件改（SPEC §2.3bis）。
3. 【原文】布局必须由「工作区创建序 + 种子」确定性重算（同种子同字节）；种子抽取 = 未用优先 + ledger 记账且只增不改（D6、REQ §110、SPEC §2.2、room-estate）。
4. 【推断】用户自定义摆放是覆盖层，只存 diff（删除的底稿 id + 新增件 + 墙挂件），渲染时合并；种子结果永不被改写，两者冲突以覆盖层为准（C3）。
5. 【原文】房间身份 = `workspaceId`，`title` 仅显示名；重名不得合并房间（OFF §0.1）。
6. 【原文】生命周期是纯函数状态机：只输出候选卡、不自发改态；时刻由调用方注入，不读钟（D1/D2/D4、room-estate）。
7. 【推断】路网必须先以图结构（节点/边/metrics/seed）存在，格坐标 poly 只是投影；「连通+环冗余」是图上的断言，不能靠画面判断（E2R §6）。

## 4. 旧仓已否决 / 反复变更的做法（避免重踩）

1. 照参考图逐件手调布局、AI 直接产出布局 → 用户明确放弃，改「人摆 + 默认预制」。REQ §38、DP「布局权移交」。
2. 生成器原始散排当候选 → 被否，要「一个个完整成品房」。REQ §47。
3. 「功能件/装饰件二分 + 面积比例撒点」降级为 v1 参考；单件级随机风格混搭禁，v2 以「套 + 规则 + 整套换风格」为准。SPEC §2.3bis。
4. 迷宫回溯路网（太密）、对称双列走廊 → 弃/禁。E2R §2/§4.1。
5. 墙带「整段滑窗采样」（§57）→ 被 §65 推翻，改为格子集合 + 邻接选件。REQ §57/§65。
6. 按 R 只改 `facing` 数值当转向 → 无帧可换，是假功能；改水平镜像。REQ §70/§75。
7. 素材渠道反复：CC0 全收（§33.8）→ MeowArt（§33.9）→ 生图锚点条件化（§39）→ 生图拆件（DP 2026-11-05）。新仓已定单一 AI 来源，勿混用。
8. 整张房间当一张背景图 → 新仓 F1 对比后否决，必须元素拆分（否则失去种子房型与自定义摆放）。
9. 缩放置换：旧仓曾把「缩小到所有房间」与「只能整数倍」判为冲突，结论是「像素大小均匀」；做 v2 相机前先读 REQ §28.5。

## 5. v1 必须支持（交付给 F2 的边界）

1. 单房 16×12 格、等距 2:1（32×16 地砖），F1-style-spec 已冻结；房型取 1 种预设拓扑，但数据结构留「拓扑模板」表（v2 扩到 8–12 种不改结构）。
2. 套模板：办公套（桌+椅+灯）、队长桌套、休憩/绿植套；每件带 footprint + 脚点。
3. 摆放硬约束：靠墙、朝门净视线、套间 ≥2 格、不压门格、门内侧主过道 ≥2 格；朝向 = 典则朝向 + 整套旋转 + 水平镜像，渲染按脚底 y 排序。
4. 每房一个 seed，同 seed 同布局，可由创建序+seed 重算（不得依赖运行时随机）；≥1 门朝走廊，窗/挂画/白板作墙挂件（`at`/`h`）。
5. 人员进出由事件驱动（Lead 常驻、worker 走入门→工位→离场）；完成类事件只改屏幕光与坐姿，不动布局（PRD §2.2）。
