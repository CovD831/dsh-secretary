# 子代理协作规范

主会话由 Opus 担任队长。子代理只承担任务卡内工作；子代理自报完成不等于验收通过。

## 1. 分工与模型分层

| 角色 | 可以做 | 不可以做 |
|---|---|---|
| Opus 队长 | 定方向、拆任务、写任务卡、处理歧义、独立验收、裁决合入 | 把验收委托给实现者；凭子代理汇报宣布完成 |
| Sonnet 实现者/审查者 | 按范围实现、补红绿测试、运行验收；审查他人改动 | 自行扩范围、改裁决、审查自己的实现 |
| Haiku 侦察/机械执行 | 搜索定位、资料清点、批量改名、格式化、重复性检查 | 架构决策、复杂实现、独立验收 |

队长先给明确任务卡再派工；范围不清、验收不可执行时不派实现任务。

## 2. 任务卡模板

以下内容可直接复制，方括号必须替换；无内容项写“无”。

```text
任务：[一句话说明唯一目标]
精炼上下文：[队长摘录本卡需要的职责/接口签名/约束/已知坑，≤40 行；与原文冲突以原文为准]
原文备查：[仅在精炼块不够时才读的文件绝对路径及章节]
允许修改：[文件绝对路径或明确目录；未列出即禁止修改]
明确不做：[功能、重构、格式化、依赖升级、提交等边界]
实现约束：[必须复用的模块、模型层级、测试与隔离要求]
验收标准：
1. 命令：[可直接执行的命令]
   期望：[关键原始输出及退出码]
2. 命令：[回归/红绿变异命令]
   期望：[关键原始输出及退出码]
交回内容：
1. 改动文件：[逐文件说明改动]
2. 验收证据：[每条命令、原始输出、退出码，不得省略失败段]
3. 未解决问题/假设：[逐项列出；没有则写“无”]
```

## 3. 串行与并行

- 主线同一时刻只能有一个实现者；不得让两个实现者写同一工作树。
- 文档、只读侦察可以并行，但输出文件不得重叠；结论由队长汇总。
- 确需并行实现时，每个任务使用独立 worktree 和独立分支，任务卡明确路径、基线与允许修改范围。
- 建树前给出回收方式；任务结束后由队长确认合入、保留或回收，不留无名树。
- 子代理不得把任务整体再次委派；需要拆分时报告队长。

## 4. 独立验收

- 子代理的“完成”“测试通过”均不算验收；队长必须亲自或派独立方重跑任务卡全部验收命令。
- 审查者不能是实现者本人；审查者核对范围、红绿 fixture、未测量分支、日志证据和安全红线。
- 修复 bug 还需确认：同一测试在修复前失败、修复后通过。缺少任一证据即退回。
- 验收失败由队长决定原实现者修复或重新派工，不得用口头解释代替证据。

## 5. 交回格式

```text
改动文件：
- [绝对路径]：[改动摘要]

验收证据：
- 命令：[完整命令]
  原始输出：[保留关键上下文，不改写结果]
  退出码：[数字]
- 修复前失败证据：[bug 修复必填，否则写“不适用”]

未解决问题/假设：
- [问题、影响、建议]；没有则写“无”

范围外发现：
- [只报告，不顺手修改]；没有则写“无”
```

只交回文本结果，不另写汇报 Markdown 文件；证据不足时必须明确写“未验收”，不得声称完成。

## 6. 安全红线

- 不读取或修改用户 `~/.dsh` 下 desktop、web、headless 的生产配置、会话和插件；测试使用独立 `DSH_HOME`。
- 不读取、打印、复制或提交凭据；任务材料中疑似凭据立即停止相关操作并报告队长。
- 不执行 `git push`，不改远端，不发布版本；提交仅在任务卡明确授权时执行。
- 不删除未经队长确认的文件、目录、worktree 或分支；生成物优先放独立临时目录。
- 不修改任务卡范围外文件，不安装未授权依赖，不执行来源不明脚本。
- 遇到红线冲突或破坏性操作需求，停止并交回，不自行放宽权限。

## 7. 任务粒度与速度

- 一张卡只交付一件可验证的东西，预计 20–40 分钟；超过就拆。
- 有未知问题（没有现成答案）的，先派限时探索卡，只交回结论与证据；拿到答案再派实现卡。
- 两档验证：迭代中跑单测与类型检查；端到端 replay 约 10 秒，改动涉及宿主交互时可随时跑。
- 互不依赖的实现卡可各用独立 worktree 并行，队长合并与验收。
- 档位映射（老板配置）：sonnet = kimi k3.1 pro（实现、审查）；haiku = deepseek v4.1 flash（侦察、机械活）。
- 卡住即停：同一问题 15 分钟无进展，停止并交回现象、已试方法与假设，由队长判断或另开探索卡。
- 坑只踩一次：撞到宿主隐性规则（命名、生命周期、路径、测试工具坑）时，交回前把规则与源码出处追加到 `.claude/skills/dsh-plugin-dev/SKILL.md` 的「已知坑」；开工前先读该节。
- 上下文注入：任务卡用「精炼上下文」块代替「背景必读」整文件清单；子代理只在精炼块不足时查原文，并在交回中注明查了什么（用于改进下一张卡的精炼块）。依据 docs/design/context-injection.md。
