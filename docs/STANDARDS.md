# DSH 秘书与判局层开发规范

适用范围：本仓全部代码、测试、脚本和提交。规则与现有裁决冲突时，以 `docs/design/NEW-REPO-BRIEF.md` 为准。

## 1. Gate 注册

- **规则**：gate 不注册就不存在。注册表是唯一定义真相；条目必须有 `id`、`插入点`、`判据`、`版本`、`红 fixture 指针`、`绿 fixture 指针`。未注册的判定代码、挂接代码和分支视为违规，必须删除；禁止以配置开关绕过注册。
- **检查**：CI 比对判定实现与注册表，发现未注册项即失败；逐项检查六字段及 fixture 文件存在。

## 2. 红绿双向 fixture

- **规则**：每个判据至少有一条应拦（红）和一条应放（绿）fixture。每次改动重跑全量；临时禁用或删除判据后，对应红用例必须失败。修 bug 必须先提交修复前失败的最小回归测试（无修复即红），再提交修复；测试和修复可在同一逻辑提交中，证据须分别展示。
- **检查**：CI 执行红绿用例，并对判据做禁用变异；红用例未失败则验收失败。修复提交须同时给出修复前失败、修复后通过的命令与输出。

## 3. 两类真相与只读投影

- **规则**：定义真相只有注册表；发生真相只有追加式事件日志 JSONL。缓存、看板、索引、内存状态和前端均为派生只读投影，不得作为判定依据，也不得回写注册表或日志。写入失败必须显式报错，不得静默产生另一份状态。
- **检查**：审查写 API 调用方；CI 搜索投影层写操作。删除派生态后从日志重建，结果与删除前一致；在真实会话各触发一次拦截和放行并回查日志。

## 4. 测量状态

- **规则**：判定结果只有 `allow`、`deny`、`unmeasured`（与 docs/EVENT-LOG-v0.md 的 gate.verdict 一致）。观察缺失、工具不可见、超时、解析失败、证据不足一律 `unmeasured`，绝不记作 `allow`；不得用默认值或历史通过记录替代本次测量。`unmeasured` 不得作为完成或放行的证据。
- **检查**：fixture 必须覆盖未观测、超时和解析失败；构造 shell 写文件任务，changed-paths 必须返回 `unmeasured`。日志不得出现无证据的 `allow`。

## 5. 比例与文件上限

- **规则**：产品 TypeScript 文件中，注释行（含块注释内部）占非空物理行不超过 **15%**；自检、测试和守护脚本总行数不超过产品代码总行数的 **100%**；单个产品文件不超过 **300** 个非空物理行。注释只解释非显然原因和约束，不复述代码；测试和守护逻辑优先复用现成 runner，不另造框架。
- **检查**：CI 用统一计数器按目录排除依赖、生成物和 fixture 数据后统计。超限提交不合入；先删除复述注释、重复测试和失效脚本，再按单一职责拆分。例外须在提交中写明文件、数值和理由，由队长单独批准，不得修改统计口径规避。
- **理由**：15% 保留必要契约说明，防止注释复述代码；100% 允许充分的独立验证，又防止守护设施膨胀超过产品；300 行迫使文件保持单一职责，针对旧仓代码与实验设施失序的问题。

## 6. 宿主与升级

- **规则**：宿主及插件构建目标钉死 **DSH 0.2.2-rc.5**，不得使用浮动版本。全部工具名、action 枚举在一个集中模块定义，其他代码只导入，不重复写字面量。升级必须先有兼容审计：重跑全部 fixture、重测秘书实际工具清单、核对钩子与事件 schema；未通过不得合入。
- **检查**：检查 manifest、锁文件和构建元数据均为 `0.2.2-rc.5`；CI 搜索散落的工具名/action 字面量。升级提交附审计命令、全量 fixture 结果和实测工具清单。

## 7. 拦截与官方代码

- **规则**：所有硬闸只在 `tools/pre-execute`（prepend）返回 deny，并附可执行修法；禁止挂接 `fs/*-intent`。不得修改官方插件的任何已有行，只 insert 自研行；官方行为变化通过适配层处理。
- **检查**：CI 搜索钩子注册点，出现 `fs/*-intent` 或其他硬闸入口即失败；逐行检查 patch/diff，确认官方行零修改、零删除。红 fixture 验证 deny 理由能回到模型。

## 8. 提交与完成声明

- **规则**：小步提交，一次提交只做一件逻辑事项；不夹带格式化、重构或无关文件。提交信息使用中文，说明动作和对象。不得提交凭据、临时产物或实验垃圾；不得推送远端。完成声明必须附可复现的独立证据，不接受“已修复”“应该通过”。
- **检查**：提交前查看 `git diff --stat` 和完整 diff，逐项对应任务。交回证据格式为“命令 + 原始输出 + 退出码”；队长或独立方重跑，不能只引用实现者自报。

## 9. 测试环境与凭据

- **规则**：测试一律使用独立、临时的 `DSH_HOME`，命令中显式设置；不得读取或修改用户 `~/.dsh` 下 desktop、web、headless 的 profile、设置、会话和插件。凭据只走受控凭据设施，不进入聊天、任务卡、日志、fixture、提交或普通文件；发现泄露立即停止并报告。
- **检查**：每条测试命令先检查 `DSH_HOME` 指向隔离目录；测试后确认用户目录无改动。检查 diff 和日志无凭据；测试记录不得粘贴环境变量值。

## 10. TypeScript 与简洁

- **规则**：产品代码使用 TypeScript，开启严格类型检查；注释、错误信息、日志使用中文。只写当前需求所需代码，不加未请求的配置层、抽象、兼容分支或错误处理；复用现有模块，不顺手改相邻代码。删除本次改动造成的孤立 import、变量和函数。
- **检查**：CI 运行类型检查、lint 和构建；审查 diff，每行能追溯到任务，新增导出均有实际调用方，无未使用符号和无关格式化。
