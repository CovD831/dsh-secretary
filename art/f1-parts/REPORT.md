# F1 元素拆分实测报告

结论：程序地墙 + AI 单件素材可组合；保持 32×16 地砖，家具优先 128×128，小人 48×64；128 家具配 2×2 格工位，不能把家具格数按 64 地砖翻倍。

| 方案 / 原生尺寸 | 清晰度与可用性 | 风格判断 |
|---|---|---|
| 程序地砖 32×16 | 可用；菱形无缝、条纹与 1px 描边清楚，细木纹少但足够 | 暖木低饱和，和立绘方向协调 |
| 程序地砖 64×32 | 可用、纹理更从容，但非必要；相同逻辑格数下地面像素 ×4 | 同上 |
| 程序两面剖面墙 | 可用；纯色、压顶、墙裙稳定，无 AI 随机形变 | 与立绘暖色协调，仍属基础几何样张 |
| 办公桌+显示器 64×64 | 勉强可用；桌、屏、键盘可辨，键盘与杯细节挤 | 接近立绘的插画式像素，轮廓偏软 |
| 办公桌+显示器 128×128 | 清晰可用，优于 64；屏和桌体轮廓明确 | 本轮最接近老板选定方向 |
| 书架 64×64 | 可用作小件；书脊、绿植可读，细部少量糊 | 协调 |
| 书架 128×128 | 清晰可用；层板、书脊、盆叶明显更好 | 协调 |
| 小人直接生成→48×64 | 可辨坐姿与朝向，但出现笔记本，五官仍偏弱 | 神态偏可爱插画，和立绘同向 |
| 小人 192×256 提示→48×64 | 两法取此；手臂、椅子、脚底略干净，但仍需像素修描 | 同向，不完全是立绘级硬像素 |

- 所有 AI 原图均为 1024×1024，API 未提供原生 64/128 输出；表中尺寸是后处理入库尺寸，不是模型真正原生绘制分辨率。
- 统一处理：去浅灰棋盘格背景→裁 bbox→LANCZOS 缩放→Oklab 量化 46 色→alpha 二值化；单件预览均为整数 2×。
- 推荐单位：**地砖 32×16（保持老板裁定）；家具 128×128 cell；小人 48×64 cell**。64×64 家具仅作低细节备选。
- 占地与锚点：桌 128 为 2×2 格、书架 128 为 1×1 格、小人 48×64 为 1×1 格；锚点均底部中心，分别约 `(64,127)`、`(64,127)`、`(24,63)`。JSON 中 64/128 各保存了像素 cell 对照，推荐以本条逻辑格数为准。
- 组装按 `x+y` 深度排序，脚底与桌脚落同一地面；128 家具搭 32×16 地砖比例合适，搭 64×32 时人物显小，应整体等比放大小人或改逻辑占地。
- 程序地板仍有两条贯穿长纹、墙段存在硬斜边；足以验证组合，不是最终入库精修。AI 家具未完全遵守严格等距桌角，后续要统一朝向与修描。
- 风格：方向一致（暖木、插画感、有神人物），但 AI 缩小件无法自动达到立绘的硬边质量；推荐大图生成 + 原生尺寸量化 + 少量人工像素修描。
- API 调用：**6 次 / 上限 12 次**，全部成功；无重试，凭据未打印或落盘。
- 产物：各单件 PNG/JSON、`room/room-test*.png`、四支脚本。实测约 **14 分钟**。
